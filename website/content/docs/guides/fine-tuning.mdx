Kev was trained on public datasets and generated policy examples. If your questions look different (your own routing categories, your own escalation rules, another language), a short fine-tune usually helps more than rewording the question. This is one of the main reasons to use an open model: with a hosted model you can't do it at all.

You don't need ML experience. You need labeled examples and a GPU for a few minutes (a free-tier Modal account works).

## Prepare your data

Put your examples in a JSONL file, one request per line. It's the same shape as an API request, plus a `label` on every question:

```json title="train.jsonl (one line, wrapped here for reading)"
{"state": {"subject": "Charged twice", "body": "I see two charges for order #4411. Please refund one."},
 "questions": {
   "team":     {"type": "choice", "instructions": "Which team should handle this ticket?",
                "criteria": {"billing": "Payments and refunds", "shipping": "Delivery problems", "access": "Login and account access"},
                "label": "billing"},
   "angry":    {"type": "noul", "instructions": "Is the customer angry?", "label": false},
   "priority": {"type": "score", "instructions": "How urgent is this ticket?", "criteria": ["low", "normal", "high"], "label": 1}}}
```

| Question type | Label |
| --- | --- |
| `choice` | the option name, e.g. `"billing"` |
| `noul` | `true` or `false` |
| `score` | the level's position, starting at 0 |

Use the exact question wording you'll use in production. Aim for a few hundred examples, and **keep 10–20% aside** in a separate `heldout.jsonl` so you can measure the result honestly.

## Train, measure, serve

<Steps>
<Step>

### Train from a released checkpoint

```bash
uv run python -m kev.train --data train.jsonl \
  --base Qwen/Qwen3.5-4B-Base --init_from jaredpalmer/kev-4b \
  --epochs 2 --lr 2e-5 --batch 1 --accum 8 --dtype bf16 --checkpointing 1 \
  --device cuda --out runs/mine
```

`--init_from` starts from what Kev already knows and adds your domain on top. Don't skip it. In one user's test on 836 support-tool decisions, training from the plain base model scored 0.33 on Kev's own evaluation set (the released model gets 0.84). The same data with `--init_from` kept 0.83 there and reached 0.88 on the new domain.

Match `--base` to the checkpoint you start from. The trainer refuses to load a mismatched base, revision, adapter rank or head size.

</Step>
<Step>

### Measure against the original

```bash
uv run python -m kev.benchmark --run jaredpalmer/kev-4b --data heldout.jsonl --out runs/before
uv run python -m kev.benchmark --run runs/mine --data heldout.jsonl --out runs/after
uv run python -m kev.compare --candidate runs/after --reference runs/before --out runs/compare
```

The report shows accuracy, [Brier score and calibration](/docs/benchmarks/metrics) per question type, so you can see which questions improved. `kev.compare` adds a confidence interval on the difference, which tells you whether the gain is real or noise.

</Step>
<Step>

### Serve it

```bash
uv run --extra serve python -m kev.serve --run runs/mine --port 8009
```

Or upload the checkpoint to a Hugging Face repo and deploy it on Modal with `KEV_MODEL=<your-org>/<your-repo>` (add `HF_TOKEN` if it's private). See [Deploy on Modal](/docs/deploy/modal).

</Step>
</Steps>

## No GPU? Let an agent do it

If you use a coding agent, the `kev-finetune` skill runs the whole recipe on Modal: it finds the questions your code already asks Jev or TypeSafe, converts labels you have (or generates enough to measure a gain), fine-tunes from a released checkpoint, fits the calibration temperature on a held-out slice, compares against the baseline, deploys an endpoint and tears everything down.

```bash
npx skills add jaredpalmer/kev@kev-finetune
```

The [skill's README](https://github.com/jaredpalmer/kev/tree/main/skills/kev-finetune) is the same recipe written for humans.

## Things to know

- **Fine-tuning can make other things worse.** Check the original benchmark as well as your own held-out set if you'll still ask general questions.
- **Re-fit calibration.** Training changes how confident the model is. The skill re-fits the temperature for you; if you train by hand, benchmark a separate held-out slice and run `uv run python scripts/calibrate_checkpoint.py --run runs/mine --rows <that run>/rows.json` before trusting thresholds. Fit on a different slice from the one you report.
- **Small GPUs work.** `--batch 1 --accum 8` in bf16 fits Kev-0.8B on a 4 GB GPU.
